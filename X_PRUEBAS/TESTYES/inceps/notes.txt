. Executive Summary: What We Built

You have created a custom Microservices Architecture. Instead of one giant computer doing everything, you built three specialized "workers" (containers) that will talk to each other.

    The Receptionist (NGINX)

        Role: Security and Traffic Control.

        What we did: We gave it an ID card (SSL Certificate) and a rulebook (nginx.conf). It stands at the front door (Port 443) and is the only one allowed to talk to the outside world (your browser).

        Key Config: It sends PHP work to the "Cook" (WordPress) on port 9000.

    The Warehouse (MariaDB)

        Role: Safe Storage.

        What we did: We built a secure vault. We wrote a script (script.sh) that opens the vault, creates a specific box for WordPress, and sets a password from your .env file.

        Key Config: We opened the internal door (bind-address=0.0.0.0) so the "Cook" can come in to get ingredients.

    The Cook (WordPress + PHP)

        Role: The Logic / The Engine.

        What we did: We installed the kitchen tools (PHP 8.2). We wrote a script (wpscript.sh) that automatically downloads the recipes (WordPress core files) and connects to the Warehouse.

        Key Config: We told it to listen on port 9000 (www.conf) so it can hear orders from the Receptionist.

2. The Architecture Diagram

This is how data flows through your system when a user visits otboumeh.42.fr.
Flow of a Request:

    The Visit: You type https://otboumeh.42.fr in Chrome.

    NGINX (Receptionist): Catches the request on port 443. It checks your SSL certificate.

        Request: "Show me the homepage."

        Action: NGINX sees it needs PHP, so it passes the request to WordPress:9000.

    WordPress (Cook): Receives the request.

        Action: It runs the PHP code. It realizes it needs the latest blog posts.

        Action: It asks MariaDB:3306 for the data.

    MariaDB (Warehouse):

        Action: Finds the data and sends it back to WordPress.

    The Result: WordPress creates the HTML page -> hands it to NGINX -> NGINX sends it to your Chrome.

3. The "Glue" We Are Missing (Docker Compose)

Right now, these three containers are like three musicians in different rooms. They can't hear each other.

We need a Conductor to:

    Network: Create a private room (network) where they can all talk.

    Volumes: Create shared storage so NGINX can see the files WordPress downloads, and MariaDB doesn't lose data when it restarts.

    Synchronization: Ensure MariaDB starts before WordPress (you can't cook without ingredients).

This Conductor is the docker-compose.yml file.
